# Adversarial review, October 9, 2026

Scope: the installed menu app, automatic controller, USB protocol, brightness bridge, diagnostic tools and installer. This review used source inspection, deliberate bad inputs, fake device replies/clocks, a deliberately broken deadline implementation and live checks against the attached pad. No low-RPM fault reproduction or forced Mac sleep was performed.

## Findings fixed

1. **Brightness requests could overwrite each other and arrive after the UI gave up.** Replaced the shared mailbox with unique request/response files. Requests have typed operations/values and expire after six seconds; the UI waits up to eight seconds for its own receipt. Stale requests cannot be replayed after reconnect. Storage is private, message reads are bounded, completed requests are removed and abandoned files expire.
2. **USB reads/writes could wedge the controller.** Replaced synchronous reports with callback-based operations and an OS timeout, plus a defensive two-second completion deadline. An absent callback exits the helper with an unconfirmed result rather than freeing an in-flight buffer or leaving the process hung. The controller prevents nested exchanges and defers stop/sleep actions until an active tick finishes.
3. **Failure status could be misleading.** Failed sends now clear the last acknowledged RPM. Sensor failures and fan-control failures have different reasons. Stale, future, malformed and oversized state are rejected; missing data remains unknown. A stale automatic controller is not labelled as manual mode. The automatic switch tracks enabled configuration so an unhealthy controller can still be switched off.
4. **Disconnect detection waited for a periodic refresh.** Added a device-removal callback and a connection check even when the fan target does not change. Reconnect still follows current chip readings; software behaviour was tested with a disconnected fake transport.
5. **Power lifecycle had gaps.** Added recovery for cancelled sleep and a missed wake notification using a clock that includes sleep. Shutdown explicitly reports whether restoring 1,500 RPM was acknowledged. These branches are implemented; physical sleep/wake remains unverified.
6. **Low-speed experiments were shipped in the everyday helper.** Production builds no longer contain the diagnostic override. A separately built diagnostic executable retains the explicitly requested timed low-speed experiment. Normal requests below 800 RPM are rejected before USB opens.
7. **Installation could leave mixed versions or overwrite a mapped executable.** Centralized atomic file replacement, added complete-bundle staging/signature verification before promotion, rollback, service-operation locking and preservation of the running automatic mode. The Python path now uses a stable executable entry point rather than a version-specific resolved Cellar path.
8. **Python imports broke the signed bundle.** Live signature verification caught a generated bytecode cache in app Resources. Bundled scripts now disable cache writes, and a new complete bundle passed strict signature verification after execution.
9. **The code was hard to audit as one file.** Split pure protocol/governor logic, hardware transport, thermals, controller lifecycle, shared requests and CLI entry point. Added a fake transport, centralized installer primitives and archived the original discovery experiment. The passive diagnostic recorder no longer performs known-rejected direct input-report reads.

## Validation

- 59 native adversarial assertions passed: valid/short/mismatched/truncated responses; device error codes; read-only busy retries; bounded retries; disconnected cached targets; invalid temperatures; malformed brightness requests; expired/future timestamps; distinct queue identities; stale/malformed status; completion signals and deadline expiry.
- Nine protocol/governor tests, five service tests and twelve installer fault/locking tests passed. Service cases cover malformed/oversized state, process mismatch, clock shifts, launchd authority and replacing a binary while its old inode is still open.
- Removing the completion deadline made the checks fail immediately at the bounded fake poll limit, rather than hang.
- Live asynchronous USB control succeeded. The installed controller resumed automatic cooling, read 42 identified chip sensors and preserved the user's 2% brightness.
- Two concurrent brightness reads each received their own acknowledged receipt. An expired request was rejected.
- A live brightness set/readback to the already-current value succeeded without changing controller PID or automatic mode.
- A real migration to EnviousCooler preserved automatic cooling and 2% brightness, removed the predecessor app/runtime and retired its service registrations.
- The installed app passed strict code-signature verification after its bundled Python service manager ran. The dashboard displayed automatic mode and 2% brightness.

## Remaining practical limits

- Temperatures use a private macOS API and the M5's exposed chip-sensor names. Future macOS changes may require revalidation.
- Requested RPM is not a measured physical fan speed. A successful USB reply proves command acceptance, not airflow or cooling effectiveness.
- The pad's reported speed (`0x0d/0x81`) is 0 when the pad's power button turns it off and follows its fan button. Calibration on 2026-10-24 (firmware 1.10) showed ramps with overshoot that settle within 50 RPM of 800, 1,500 and 3,200 RPM commands after 12 seconds. No independent tachometer confirmed it is a measurement. Sustained mixed fan and lighting traffic at the new polling rate is not verified on hardware.
- Red-light cycling appears related to the former low-speed curve but its exact threshold and a corresponding USB fault signal are not established.
- Physical unplug/replug, next-login and system sleep/wake have not been exercised in this review. The software paths and guards do not substitute for those hardware checks.
- An OS/driver failure can leave a hardware command outcome uncertain. The UI and receipts report that uncertainty; they cannot promise physical restoration without an acknowledgement.

Codex final review: all-clear for the reviewed local software changes after the confirming build/tests, installed-device checks and signature verification. Hardware observations above remain explicitly bounded. No network service, cloud spend or additional privacy permission was introduced.
